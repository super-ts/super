État local

L'état local appartient à une instance de composant : privé, créé avec elle, perdu avec elle. Il sert aux données d'interface ; les données de l'app vivent dans un store.

Créer un état local

ÉcritureRôle
@state local = initial;Déclare l'état dans le corps de la classe, qui se lit ensuite par this.local (voir les déclarations). La valeur initiale est copiée. Dans un composant écrit en .ts, l'équivalent est local = this.state(initial), dans un champ ou le constructeur uniquement (pendant render, il lève une erreur).
get()La valeur courante, figée. À appeler dans render pour refléter le dernier changement.
set(patch)Fusionne le patch (un niveau), puis re-rend le composant. Accepte un objet partiel ou une fonction (courant) => patch.

Plusieurs set d'affilée ne donnent qu'un seul rendu.

Le type, et null as string | null

@state ne porte pas de type : il vient de la valeur initiale (écrire @state local: … = … est une erreur). @state local = { message: null }; donnerait un champ de type null, et this.local.set({ message: 'ok' }) ne compilerait pas. On élargit donc avec as les champs qui changeront de type :

État local ou store ?

Dans l'état localDans un store
Un message de confirmation affiché sous des boutonsLes valeurs des compteurs
Un panneau ouvert ou fermé, un onglet actifUn « chargement en cours » que plusieurs composants affichent
Une saisie en cours, avant validationLes données validées et persistées
La question d'un dialogue ouvertUne erreur de chargement à montrer sur plusieurs écrans

Les questions à se poser :

  • Un autre composant en a-t-il besoin ? Si oui, store.
  • Doit-elle survivre à la navigation ? Si oui, store. L'état local disparaît avec l'écran : en revenant sur « Cafés », le message de la visite précédente n'est plus là, et c'est ce qu'on veut.
  • Est-ce une donnée de l'app ou un détail d'affichage ? Donnée de l'app : store.

Ce qu'il faut savoir

  • Privé : seul ce composant le lit et l'écrit. Ni le store, ni le parent, ni les autres composants n'y ont accès.
  • Par instance : deux écrans montés en même temps ont chacun le leur.
  • Lié à l'instance : il naît avec le composant et disparaît avec lui. Un élément déplacé par une boucle for avec key le garde ; un composant que le parent cesse de rendre puis rend de nouveau est une nouvelle instance, avec un état neuf.
  • Réactif : set re-rend le composant, comme un changement de store.
  • C'est l'équivalent du useState de React, regroupé dans un seul objet.
