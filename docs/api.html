@super-ts/core

Exports: SuperContract, SuperStore, CommandFailure, and types.

SuperContract

A command has at most one parameter, the body, and declares void or Outcome<Result, Reasons>. Selectors are memoised; pending is provided by Super and cannot be declared. See Contracts and Selectors.

SuperStore

this.selectors.x(…)The contract's selectors on the current state, plus pending(…).

The state can be neither read nor changed in the constructor. Commands<Self> checks that each command of the contract has a method with identical parameters, returning only the declared result, and that no public method is outside the contract.

@super-ts/dom

Exports: SuperElement, html, nothing, repeat, createApp, CONTEXT_REQUEST, defineRouter, params, query, createRouter, RouterOutlet, redirect, and types.

A .super component

A component is written in a .super file: a TypeScript module whose class methods emit elements. It exports a class that extends SuperElement, like any module: the API below does not change. Its only import from @super-ts/dom is usually SuperElement (and RouterOutlet for a layout).

  • An import without extension finds the .super: import { NotFoundScreen } from '@components/not-found' loads not-found/index.super, from a .super as from a .ts (routes.ts, main.ts, a test), with the types.
  • A method that emits elements (render, renderError, a #private method) returns nothing: return; stops and keeps what was emitted, return x; does not compile.
  • Declarations are written in the class, without a generic: @tag, @prop, @emit, @title, and for setup @contract, @selector, @state, @form, @ref, @on (see Component declarations and Setting up). A component written in a .ts keeps static tag, the generic SuperElement<{ props; emits }> and the methods (this.contract(…), this.selector(…)…).
  • A module without a template (contract, store, domain, routes, main.ts, test) stays a .ts.

See Templates for the syntax, and Tooling for type checking and the editor.

SuperElement

MemberRole
@tag = 'x-y';The custom element's name: required (except for an abstract class), a lowercase string with a hyphen. Replaces static tag in a .super.
@prop name: T;A prop: required (name: T), optional (name?: T) or with a default value computed once per instance (name: T = value). No HTML element property names (id, title…); page is reserved. See Component declarations.
@emit name: T;An event emitted to the parent (void if it carries nothing).
@title = …;The page title while the component is mounted: a string, or a tracked function (recomputed after each render). See The page title.
this.nameA declared prop, readable from the fields onwards, always at its current value. A copy made at construction does not follow changes: read it in render or selector for an up-to-date value.
this.propsAll props, read-only, in one object. In a .super, you read each prop via this.name.
@contract name;, @contract name = 'contract';The view of the store provided for this contract, read via this.name: selectors, send (without waiting), on. Once per contract, all contracts except the router. .ts form: this.contract(name). See Reading a store.
this.routerThe view of the app's router, with no declaration and readable everywhere (render included): the active route current (name(), path(), params.x(), query.x()), a specific route at(name), commands navigate, visit, back, and href. See The router in a component.
this.page.title = …Sets the page title (TitleValue: a string or a tracked function) while the component is mounted. In a field or the constructor, reapplied on each mount (what @title does); once mounted, replaces the component's title until unmount. Write-only; forbidden during render. The last mounted component that sets a title wins.
@selector name = read;{ value }: a selector's value, as is; the component only re-renders if it changes. On a route value (@selector id = this.router.current.params.id;), also isValid(). .ts form: this.selector(read).
@state name = initial;{ get(), set(patch) }. .ts form: this.state(initial). See Local state.
@form name = options;A form. .ts form: this.form(options). See Forms.
@ref name: T;A reference to a template element, set by ref={this.name} (rejected if the tag is not a T); .value is undefined until the element is rendered. .ts form: this.ref<T>().
@on('contract', 'event') method(payload) { … }A listener on a method, called on each event while the component is mounted; the parameter is typed by the event. No need for @contract; 'router' listens to the router. .ts form: this.contract('contract').on('event', …) in the constructor. See Listeners.
this.emit(name, payload?)Event declared by @emit, sent to the parent, listened to with on:name={…} on the tag (or { on: { name } } with create).
this.signalAborted on unmount.
mounted(), unmounted()After the first render, on each mount; on unmount.
render()Emits the component's HTML, on each render. render() {} renders nothing.
renderError(error)Optional: emits its elements instead of render if render or a descendant crashes. See Errors.

@contract, @selector, @state, @form, @ref and @on are declared in the class body; in a .ts, their methods are called in a field or the constructor, never during render, and throw an error otherwise; this.page.title cannot be set during render either. See Components and Parents and children.

html, nothing and repeat (lit-html) remain exported for code that is not a component; they are no longer used to write a component. See Templates, and What about html, nothing, repeat?.

Router

The title is configured in the createRouter options, not in defineRouter (whose keys are routes). Without default, the document's original title comes back. See Router and The page title.

RULES, ALIASESWhere SuperContract/SuperStore (@core) and SuperElement (@components) are imported; the @core and @components aliases.
