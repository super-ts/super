SuperContract

Une commande a au plus un paramètre, le body, et déclare void ou Outcome<Résultat, Raisons>. Les sélecteurs sont mémoïsés ; pending est fourni par Super et ne peut pas être déclaré. Voir Contrats et Sélecteurs.

@super-ts/dom

Exports : SuperElement, html, nothing, repeat, createApp, CONTEXT_REQUEST, defineRouter, params, query, createRouter, RouterOutlet, redirect, et des types.

Un composant .super

Un composant s'écrit dans un fichier .super : un module TypeScript dont les méthodes de classe émettent des éléments. Il exporte une classe qui étend SuperElement, comme n'importe quel module : l'API ci-dessous ne change pas. Son seul import de @super-ts/dom est en général SuperElement (et RouterOutlet pour une mise en page).

  • Un import sans extension trouve le .super : import { NotFoundScreen } from '@components/not-found' charge not-found/index.super, depuis un .super comme depuis un .ts (routes.ts, main.ts, un test), avec les types.
  • Une méthode qui émet des éléments (render, renderError, une méthode #privée) ne renvoie rien : return; s'arrête en gardant ce qui est émis, return x; ne compile pas.
  • Les déclarations s'écrivent dans la classe, sans générique : @tag, @prop, @emit, @title, et pour la préparation @contract, @selector, @state, @form, @ref, @on (voir Déclarations du composant et Préparer). Un composant écrit dans un .ts garde static tag, le générique SuperElement<{ props; emits }> et les méthodes (this.contract(…), this.selector(…)…).
  • Un module sans template (contrat, store, domaine, routes, main.ts, test) reste un .ts.

Voir Templates pour la syntaxe, et Outillage pour la vérification des types et l'éditeur.

SuperElement

MembreRôle
@tag = 'x-y';Le nom du custom element : obligatoire (sauf classe abstract), une chaîne en minuscules avec un tiret. Remplace static tag dans un .super.
@prop nom: T;Une prop : obligatoire (nom: T), facultative (nom?: T) ou avec une valeur par défaut calculée une fois par instance (nom: T = valeur). Pas de nom de propriété des éléments HTML (id, title…) ; page est réservé. Voir Déclarations du composant.
@emit nom: T;Un événement émis vers le parent (void s'il ne transporte rien).
@title = …;Le titre de la page tant que le composant est monté : une chaîne, ou une fonction suivie (recalculée après chaque rendu). Voir Le titre de la page.
this.nomUne prop déclarée, lisible dès les champs, toujours à sa valeur courante. Une copie faite à la construction ne suit pas les changements : lire dans render ou selector pour une valeur à jour.
this.propsToutes les props, en lecture seule, en un objet. Dans un .super, on lit chaque prop par this.nom.
@contract nom;, @contract nom = 'contrat';La vue du store fourni pour ce contrat, lue par this.nom : selectors, send (sans attente), on. Une fois par contrat, tous les contrats sauf le router. Forme .ts : this.contract(nom). Voir Lire un store.
this.routerLa vue du router de l'app, sans déclaration et lisible partout (render compris) : la route active current (name(), path(), params.x(), query.x()), une route précise at(nom), commandes navigate, visit, back, et href. Voir Le router dans un composant.
this.page.title = …Pose le titre de la page (TitleValue : une chaîne ou une fonction suivie) tant que le composant est monté. Dans un champ ou le constructeur, repris à chaque montage (ce que fait @title) ; une fois monté, remplace le titre du composant jusqu'au démontage. En écriture seulement ; interdit pendant render. Le dernier composant monté qui pose un titre l'emporte.
@selector nom = lecture;{ value } : la valeur d'un sélecteur, telle quelle ; le composant ne se re-rend que si elle change. Sur une valeur de route (@selector id = this.router.current.params.id;), aussi isValid(). Forme .ts : this.selector(lecture).
@state nom = initial;{ get(), set(patch) }. Forme .ts : this.state(initial). Voir État local.
@form nom = options;Un formulaire. Forme .ts : this.form(options). Voir Formulaires.
@ref nom: T;Une référence vers un élément du template, posée par ref={this.nom} (refusée si la balise n'est pas un T) ; .value vaut undefined tant que l'élément n'est pas rendu. Forme .ts : this.ref<T>().
@on('contrat', 'événement') méthode(payload) { … }Un écouteur sur une méthode, appelée à chaque événement tant que le composant est monté ; le paramètre est typé par l'événement. Pas besoin de @contract ; 'router' écoute le router. Forme .ts : this.contract('contrat').on('événement', …) dans le constructeur. Voir Les écouteurs.
this.emit(nom, payload?)Événement déclaré par @emit, vers le parent, écouté par on:nom={…} sur la balise (ou { on: { nom } } avec create).
this.signalAvorté au démontage.
mounted(), unmounted()Après le premier rendu, à chaque montage ; au démontage.
render()Émet le HTML du composant, à chaque rendu. render() {} ne rend rien.
renderError(error)Facultatif : émet ses éléments à la place de render si render ou un descendant plante. Voir Gérer les erreurs.

@contract, @selector, @state, @form, @ref et @on se déclarent dans le corps de la classe ; dans un .ts, leurs méthodes s'appellent dans un champ ou le constructeur, jamais pendant render, et lèvent une erreur sinon ; this.page.title ne se pose pas non plus pendant render. Voir Composants et Parents et enfants.

@super-ts/vite

Les briques du plugin sont exportées aussi, pour un outillage maison :

RULES, ALIASESOù s'importent SuperContract/SuperStore (@core) et SuperElement (@components) ; les alias @core et @components.
checkModule, checkCoreImports, checkComponentImports(cheminRelatif, code) : le message d'erreur si le module enfreint une règle, null sinon.
contractsIn, scanContracts, scanRouterLisent les contrats d'un fichier ou de src/@core/, et le router de l'app.
contractsModule, contractsDeclarationProduisent le module qui inscrit les contrats, et le contenu de contracts.d.ts.
hotModuleCode(code) : le code ajouté en dev à un module de composant pour le remplacement à chaud, null s'il ne déclare aucun composant.

Le plugin compile aussi chaque .super en TypeScript, puis en JS, avec une source map vers le .super, et ajoute .super aux extensions résolues. Voir Architecture et Outillage.
