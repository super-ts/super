Examples

Super's examples live in a single app, examples/demo. Its home page leads to each one: counters, form, shop, errors, widget, composition, UI kit. This page says which file shows which concept.

Running the app

To follow the "See the file" links from these docs to the code, open the docs with npm run docs (it then serves the whole repository), or open docs/index.html directly in a browser.

What the examples share

The app follows Super's layout: one folder per contract under src/@core/ (contract.ts, store.ts, store.test.ts), one folder per screen under src/@components/ (index.super, its stylesheet index.css, its test index.test.ts, and its sub-components flat beside it), reusable components in @components/shared/, and the domain in src/domain/. The rest (ports/, adapters/, routes.ts, main.ts, widgets/) is user-land. Components are .super files (see Templates); everything else, tests included, is in .ts.

Example: the UI kit

/kit is the kit's table of contents: one page per family of @super-ts/ui components, wired to the demo's stores. Each page shares the same layout (KitPage: a "← The kit" link, a title, an introduction, the content), and has its own route:

PageRouteWhat it shows
Forms and commands/kit/formsThe form is submitted to the profile store (taken@example.com is an address already taken), and the command button really resets the coffee counter to zero.
Windows/kit/windowsA dialog, a modal and a confirmation, rendered according to local state.
Primitives/kit/primitivesA menu, a popover, a tooltip, tabs, a collapsible content, a combobox with hard-coded values, and a combobox that looks up its suggestions in the dummyjson.com API.
Display/kit/displayThe button variants, badges, spinners, a skeleton, an empty state and an error panel.
Table/kit/tableA static table on the counters, and a table connected to the public dummyjson.com test API, whose sort order and page live in the URL.
Theme/kit/themeThe ways to override the kit's style, each next to its effect: the whole app, a zone, the dark theme forced in a zone, an instance, an ordinary rule, a dense table.

The connected table follows the demo's ports and adapters: the catalogue store only knows the ProductCatalog port; main.ts gives it the dummyjson.com adapter, the tests an in-memory adapter that sorts, paginates and searches like the server. The store ignores a response overtaken by a more recent request: sorting twice in a row cannot display the page of the first sort.

The "Theme" page displays the code it applies: each CSS file is imported twice, once to be applied, once as text through the Vite suffix ?raw (import ZONE_CSS from './theme-zone.css?raw'), displayed in a <pre>. The code shown therefore cannot drift from the code applied.
