Exemples

Les exemples de Super vivent dans une seule app, examples/demo. Sa page d'accueil mène à chacun : compteurs, formulaire, boutique, erreurs, widget, composition, kit d'interface. Cette page dit quel fichier montre quel concept.

Lancer l'app

Pour suivre les liens « Voir le fichier » de cette doc vers le code, ouvre la doc avec npm run docs (elle sert alors tout le dépôt), ou ouvre directement docs/index.html dans un navigateur.

Ce qui est commun aux exemples

L'app suit l'organisation de Super : un dossier par contrat sous src/@core/ (contract.ts, store.ts, store.test.ts), un dossier par écran sous src/@components/ (index.super, sa feuille index.css, son test index.test.ts, et ses sous-composants à plat à côté), les composants réutilisables dans @components/shared/, et le métier dans src/domain/. Le reste (ports/, adapters/, routes.ts, main.ts, widgets/) est du user-land. Les composants sont des fichiers .super (voir Templates) ; tout le reste, tests compris, est en .ts.

/counters liste des compteurs (cafés, pompes, livres lus) ; /counters/:id affiche un compteur avec des boutons + et −. Les valeurs sont enregistrées dans le localStorage.

Exemple : le formulaire de profil

/profile est un formulaire avec chaque type de champ. Il est soumis à un serveur simulé par un adapter, avec de la latence. Pour voir chaque cas : taken@example.com est une adresse déjà prise, une adresse contenant offline provoque une panne réseau, une image de plus de 1 Mo est refusée.

@core/profile/store.test.ts et adapters/fake-profile-client.test.tsLe store et l'adapter testés seuls.Tester

Exemple : le kit d'interface

/kit est le sommaire du kit : une page par famille de composants de @super-ts/ui, branchée sur les stores de la démo. Chaque page partage la même mise en page (KitPage : un lien « ← Le kit », un titre, une présentation, le contenu), et a sa propre route :

PageRouteCe qu'elle montre
Formulaires et commandes/kit/formsLe formulaire est soumis au store du profil (taken@example.com est une adresse déjà prise), et le bouton de commande remet vraiment le compteur des cafés à zéro.
Fenêtres/kit/windowsUn dialogue, une modale et une confirmation, rendus selon l'état local.
Primitives/kit/primitivesUn menu, un popover, une info-bulle, des onglets, un contenu repliable, un combobox à valeurs en dur, et un combobox qui cherche ses suggestions dans l'API dummyjson.com.
Affichage/kit/displayLes variantes de bouton, les badges, les spinners, un squelette, un état vide et un panneau d'erreur.
Table/kit/tableUne table statique sur les compteurs, et une table branchée sur l'API publique de test dummyjson.com, dont le tri et la page vivent dans l'URL.
Thème/kit/themeLes manières de surcharger le style du kit, chacune à côté de son effet : toute l'app, une zone, le thème sombre forcé dans une zone, une instance, une règle ordinaire, une table dense.

La table branchée suit les ports et adapters de la démo : le store du catalogue ne connaît que le port ProductCatalog ; main.ts lui donne l'adapter sur dummyjson.com, les tests un adapter en mémoire qui trie, pagine et cherche comme le serveur. Le store ignore une réponse dépassée par une demande plus récente : trier deux fois de suite ne peut pas afficher la page du premier tri.

La page « Thème » affiche le code qu'elle applique : chaque fichier CSS y est importé deux fois, une fois pour être appliqué, une fois en texte par le suffixe Vite ?raw (import ZONE_CSS from './theme-zone.css?raw'), affiché dans un <pre>. Le code montré ne peut donc pas s'écarter du code appliqué.
