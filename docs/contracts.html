Contracts

A contract describes a store from the outside: what you can read, what you can ask of it, what it announces. It is the only thing a component knows about a store.

Declaring a contract

A contract comes in three pieces:

  1. A type (CounterTypes) that describes its state, its commands and its events, for the compiler.
  2. A class that extends SuperContract<CounterTypes> and names itself in its constructor: super({ name: 'counter' }). This name is the contract's key throughout the app: a component declares @contract counter;, a store declares super({ contract: 'counter', … }).
  3. Methods, optional: each one is a selector, a permitted read of the state (see Selectors).

A contract lives in src/@core/<name>/contract.ts, one folder per contract, next to its store. The Vite plugin reads these files and generates src/@core/contracts.d.ts, the name → class dictionary that types @contract counter;, @on('counter', …) and StoreOfContract<'counter'>. This file is committed, but never written by hand.

This minimal contract is valid:

state: the interface of the state

state is the type of what the store keeps in memory. It sets the shape of the initialState passed to the store's constructor, what the store reads with this.get() and changes with this.set(), and the first parameter of the selectors. Components never see this interface: they read through the selectors.

commands: the requests

A command is a request addressed to the store. It takes at most one parameter, the body (an object, more readable and extensible than several arguments), and nothing comes back to whoever sends it. In practice, a command often changes the state, but not necessarily. The rule that matters goes the other way: only the store changes its state.

A command declares one or the other:

  • void: it has no particular outcome to publish (apart from an unexpected failure).
  • Outcome<Result, Reasons>: what its success produces (published in increment:done), and the closed list of its failure reasons (published in increment:failed). See Declaring the outcome.

This is a design choice: the component sends and moves on, and Super publishes the outcome to everyone who listens to it. void is enough even if the store's method is async.

events: the announcements

In the Shop example: cart/contract.ts.

Each command already has its events, published by Super: increment:done and increment:failed. The events key is for the other facts the store announces, those that are not the outcome of a single command. An event pairs a name with its payload. Only the store emits (with this.emit); anyone can listen: components, other stores, tests.

An event with a payload is written synced: { at: number } and emitted with this.emit('synced', { at: Date.now() }).

What a contract is not

  • Not an implementation. It does not say how commands are handled: that is the store's role.
  • Not an instance. A contract holds no state. There can be several stores for the same contract (one per test, for example).
  • Not the store's dependencies. The CounterRepository does not appear in the contract: it is an implementation detail, declared by the store's constructor.

At runtime, Super only reads a contract's name and methods (the selectors). The types state, commands and events exist only for the compiler.

Pitfalls

A misspelt key is rejected command instead of commands (or event instead of events) does not compile: the error appears on super({ name }), with the offending key and the expected keys ("unknown key in the contract types: command (expected: state, commands, events)").
The name is written out in full The plugin reads super({ name: 'counter' }) in the source: the name must be a string literal. Two contracts with the same name are rejected, and 'router' is reserved for the app's router.
The selectors' state is annotated by hand TypeScript does not infer a method's parameters: write count(s: CounterState, id: string). This first parameter is checked at the store's declaration (SuperStore<CounterContract>): a type that does not accept the contract's state does not compile.
