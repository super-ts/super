Local state

Local state belongs to a component instance: private, created with it, lost with it. It is for interface data; the app's data lives in a store.

Creating local state

SyntaxRole
@state local = initial;Declares the state in the class body, which is then read through this.local (see the declarations). The initial value is copied. In a component written in .ts, the equivalent is local = this.state(initial), in a field or the constructor only (during render, it throws an error).
get()The current value, frozen. Call it in render to reflect the latest change.
set(patch)Merges the patch (one level), then re-renders the component. Accepts a partial object or a function (current) => patch.

Several set calls in a row give only one render.

The type, and null as string | null

@state carries no type: it comes from the initial value (writing @state local: … = … is an error). @state local = { message: null }; would give a field of type null, and this.local.set({ message: 'ok' }) would not compile. So you widen with as the fields that will change type:

Local state or store?

In local stateIn a store
A confirmation message shown under buttonsThe counters' values

The question of an open dialogA load error to show on several screens

The questions to ask yourself:

  • Does another component need it? If so, store.
  • Must it survive navigation? If so, store. Local state disappears with the screen: when you come back to "Coffees", the message from the previous visit is gone, and that is what you want.
  • Is it app data or a display detail? App data: store.

What you need to know

  • Private: only this component reads and writes it. Neither the store, nor the parent, nor other components have access to it.
  • Per instance: two screens mounted at the same time each have their own.
  • Tied to the instance: it is born with the component and disappears with it. An element moved by a for loop with key keeps it; a component that the parent stops rendering then renders again is a new instance, with fresh state.
  • Reactive: set re-renders the component, like a store change.
  • It is the equivalent of React's useState, grouped in a single object.
