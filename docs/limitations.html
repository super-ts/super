Limitations

Super is a draft. Here is what it does badly or checks badly today. What it does not do yet is in Roadmap and open questions.

Known limitations

Typing

  • The parameters of a store method are annotated by hand: TypeScript does not infer the parameters of a class method. implements Commands<…> only checks that they are equal to those of the contract.
  • this.fail accepts every reason declared by the contract, not only those of the current command.

Architecture plugin

  • It reads the code as text: it sees named imports (including renamed ones), not an import * as dom from '@super-ts/dom' outside the required folders.
  • It recognises a contract by its declaration export class X extends SuperContract, followed by super({ name: '…' }) with a name written out literally.
  • Nothing stops a component from importing a store exported by a user-land module.

Components

  • A component does not catch the error of its own constructor: only the renderError of an ancestor can.
  • @selector only accepts the value of a selector, as is: a condition or a computation goes in render, or in a new selector of the contract.
  • A prop or a field cannot carry the name of a property of HTML elements (id, title, hidden, slot…): it is a type error. A route parameter id is therefore read into a field with another name (counterId = this.router.current.params.id;), and a title prop becomes heading. This is also why the content written between the tags fills a content prop and not children, a native property of elements.
  • page is a reserved name in a component: it is this.page, which carries the page title.
  • A tracked title (@title = () => …) is only recomputed when the component that sets it renders. What it reads is tracked like the reads of render: a value read by the title alone therefore re-renders the whole component when it changes, and a value Super does not track (an ordinary field, the time) only updates it on the next render.
  • A child component is written by its class (<CounterScreen />): a <counter-screen> tag written by its tag name is not supported.
  • Hot replacement reloads the page when a component changes its fields, or has #private members, methods included (see Hot replacement).

.super files

The syntax is at version 0 (packages/lang/SPEC.md). Its deliberate limitations:

  • No directive on a component ({form.field('x')} in its tag): a component receives props, on:, children and named slots.
  • On a native tag, on: only accepts the events of that tag: listening on a <div> for a custom event bubbled up from a child is not allowed.
  • A generic call signature in a type literal ({ <T>(x: T): T }) is taken for an element: move it into a type or an interface in a .ts file.
  • @prop, @emit and the preparation declarations (@contract, @selector, @state, @form, @ref, @on) are valid TS (decorated fields and methods), but @tag = … and @title = … are not: only our tools know them (the .super formatter, the Tree-sitter grammar, the language server). An editor without them shows them as errors.
  • The event name of @on is a string written as is: no template literal (@on('counter', `${change}:done`)) and no loop over a list of events. Listening to several events takes one method per event, which can call the same private method (the counter screen has onIncremented, onDecremented, onReset… which call #done).
  • No type on @contract, @selector, @state or @form: it comes from the value. To widen it, write as in the value (@state local = { message: null as string | null };). @ref is the opposite: a type, without a value.
  • The old form (cart = this.contract('cart');, this.selector(…), this.state(…), this.form(…), this.ref<T>(), .on(…) in the constructor) is rejected in a .super file. A component written in .ts keeps these methods, which remain the only possible way to write it outside .super files.

And on the tooling side (see Tooling):

  • Biome does not read .super files: their TS is formatted by Biome through the .super formatter, but the order of their imports is not checked.
  • In Zed, the .super extension (editors/zed) is installed as a dev extension, and its grammar (editors/tree-sitter-super) is compiled from a local git repository, referenced by an absolute path in extension.toml until the grammar is published.
  • The language server runs on TypeScript 6, because Volar does not support TypeScript 7 yet. The command-line check (npm run typecheck) uses the repository's TypeScript 7.

Rendering

  • Selector tracking stops at the first level of the state: a selector that reads a list is recomputed as soon as one item changes. A selector that builds large objects per item then pays for a full walk of its result.
  • The selector cache keeps one result per set of primitive arguments (a sku, an id) for the whole life of the store.
  • Freezing the state only goes down into arrays and plain objects: the content of a Map, a Set or an instance stays mutable, and such a mutation escapes tracking.
  • Errors from code Super does not see (setTimeout, a listener set by hand on window) only go to the console.

Router

  • Guards are synchronous, and there is no exit guard ("unsaved changes").
  • No base path (application served under /app/).
  • The described types are limited to String, Number, Boolean, { oneOf } and their lists: no date, no object, no custom conversion.
  • A { oneOf } list that leaves out a value of the union compiles: only an extra value is rejected. The value left out is never valid in the URL.
  • No shortcut to change a single query key: a navigation gives the whole query again ({ ...currentValues, sort: 'value' }).
  • Only one typed router per app: the plugin rejects two defineRouter declarations.

UI kit

  • No layout component (Stack, Grid, Card): layout stays in the app's CSS.
  • fieldOf is written in the render of the component that owns the form: a kit field placed in a child component would no longer follow the form.
  • Floating elements (menu, popover, tooltip, combobox list) do not use the browser's popover API: an ancestor with overflow: hidden can clip them.
  • A few built-in texts do not have a prop to change them yet ("Checking…", the table pagination). See Kit limitations.

Distribution

  • The packages are in 0.x: a minor version can break the API. They all share one version, so install them at the same version.

What is still missing, the follow-ups set aside and the questions under discussion are in Roadmap and open questions.
